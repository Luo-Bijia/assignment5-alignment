> 先把每条 rollout 变成一个标量 advantage，再把这个 advantage 乘到该回答每个 token 的 log-prob 上

这一步就是 policy gradient 最关键的“桥梁”之一：

> 它把不可微的离散采样与 reward 判断，转换成了一个能够对模型参数反向传播的可微目标。

但要特别准确地理解：不是让 reward 或采样过程本身变得可微，而是通过 log-derivative trick 构造了一个可微的替代目标。

## 1. 原始问题为什么不可微

模型先离散采样出回答：

\[
y\sim\pi_\theta(y\mid x)
\]

然后 reward function 判断：

\[
r(y\mid x)\in\{0,1\}
\]

这里包含两个不可微环节：

- token 是离散采样出来的；
- reward 可能来自字符串解析、答案比较、单元测试。

你不能直接从 `reward=1` 沿着“字符串生成过程”做普通反向传播。

## 2. Policy gradient 如何绕过它

我们真正想最大化：

\[
J(\theta)=\mathbb E_{y\sim\pi_\theta}[r(y)]
\]

通过 log-derivative trick （推导在下方）可以得到：

\[
\nabla_\theta J
=
\mathbb E[
r(y)\nabla_\theta\log\pi_\theta(y)
]
\]

加入 baseline 后，把 reward 换成 advantage：

\[
\nabla_\theta J
\approx
\mathbb E[
A(y)\nabla_\theta\log\pi_\theta(y)
]
\]

于是可以构造可微目标：

\[
A(y)\log\pi_\theta(y)
\]

PyTorch 做梯度下降，所以实际 loss 写成：

\[
\boxed{
L(y)=-A(y)\log\pi_\theta(y)
}
\]

这就是你代码中的：

```text
per-token loss = -advantage × log-prob
```

## 3. 为什么乘上 advantage 就产生“偏好”

梯度是：

\[
\nabla_\theta L
=
-A\nabla_\theta\log\pi_\theta(y)
\]

因此：

### `A > 0`

这条回答比同题其他回答好：

\[
L=-A\log\pi(y)
\]

梯度下降会提高这条回答的 log-prob，也就是让模型以后更容易生成类似行为。

### `A < 0`

这条回答比同题其他回答差。

梯度下降会降低这条回答的 log-prob，让模型以后更不容易重复这种行为。

### `A = 0`

这条回答没有相对优势：

\[
\nabla_\theta L=0
\]

它不为本次更新提供训练信号。

所以 advantage 同时决定：

- 方向：提高还是降低概率；
- 强度：提高或降低多少。

这就是离散 reward/preference 最终作用到连续模型参数上的方式。

## 4. 为什么要乘到每个 response token

自回归模型对整个回答的概率是：

\[
\pi_\theta(y\mid x)
=
\prod_{t=1}^{L}
\pi_\theta(y_t\mid x,y_{<t})
\]

取对数后，乘积变成求和：

\[
\log\pi_\theta(y\mid x)
=
\sum_{t=1}^{L}
\log\pi_\theta(y_t\mid x,y_{<t})
\]

所以序列级目标：

\[
-A(y)\log\pi_\theta(y\mid x)
\]

可以展开成：

\[
-A(y)
\sum_{t=1}^{L}
\log\pi_\theta(y_t\mid x,y_{<t})
\]

也就是：

\[
\sum_{t=1}^{L}
\left[
-A(y)\log\pi_\theta(y_t\mid x,y_{<t})
\right]
\]

这正对应你的实现：

1. 每条回答有一个 advantage `[N]`
2. 扩展成 `[N,1]`
3. 乘到该回答所有 token 的 log-prob `[N,T]`
4. 得到 per-token loss `[N,T]`

## 5. 这里的计算图到底经过哪里

计算图是：

```text
model parameters θ
        ↓
      logits
        ↓
    log_softmax
        ↓
实际 response token 的 log_probs
        ↓
乘以固定 advantage
        ↓
       loss
        ↓
     backward
```

计算图不经过：

```text
离散采样
reward parser
答案比较
group normalization
```

这些步骤只是计算一个外部权重 `A`。在当前实现中，advantage 是没有梯度的普通 tensor，可以理解为：

> reward 系统给模型的梯度贴上一个“方向与力度标签”。

真正可微的是模型重新计算出来的 `log_probs`。

## 6. 为什么还要 mask、token 聚合和回答聚合

完整的单条回答 loss 类似：

\[
L_j
=
-\frac{A_j}{\operatorname{len}(y_j)}
\sum_{t=1}^{\operatorname{len}(y_j)}
\log\pi_\theta(y_{j,t}\mid x_j,y_{j,<t})
\]

其中：

- `response_mask`：只训练 response，不训练 prompt 和 padding；
- token 求和：把 token-level log-prob 还原为 sequence-level log-prob；
- 除以 response length：避免长回答只因 token 多就产生更大的梯度；
- 对回答求平均：用 `B×G` 条采样近似期望；
- microbatch 加权：只是在不改变完整 batch 梯度的前提下降低显存占用。

最终整个 rollout batch 的近似目标是：

\[
L
=
-\frac{1}{BG}
\sum_{i=1}^{B}
\sum_{j=1}^{G}
\frac{A_{i,j}}{\operatorname{len}(y_{i,j})}
\sum_t
\log\pi_\theta(y_{i,j,t}\mid x_i,y_{i,j,<t})
\]

## 7. microbatch 不属于 RL 数学本身

microbatch 只是工程实现：

```text
完整 rollout batch
→ 切成若干小块
→ 分别 forward/backward
→ 梯度累积
→ 最后只 optimizer.step 一次
```

只要每个 microbatch 按其样本数占完整 batch 的比例加权，结果就等价于一次处理完整 rollout batch。

所以整件事可以分成两层：

- RL 核心：`advantage × ∇log-prob`
- 工程实现：mask、长度归一化、batch 平均、gradient accumulation、gradient clipping

最凝练地说：

\[
\boxed{
\text{离散 reward 决定 }A
\quad\Longrightarrow\quad
A\text{ 调制可微的 }\log\pi_\theta
\quad\Longrightarrow\quad
\text{梯度改变模型概率}
}
\]

所以你的理解是对的：`advantage × token log-prob` 正是将离散的“这个回答更好/更差”转化为神经网络可执行梯度更新的核心连接点。


-----

\[
J(\theta)=\mathbb E_{y\sim\pi_\theta}[r(y)]
\]

->

\[
\nabla_\theta J
=
\mathbb E[
r(y)\nabla_\theta\log\pi_\theta(y)
]
\]


核心只用了两步：把“期望”展开成加权求和，再使用 \(\nabla\log p=\frac{\nabla p}{p}\)。

先暂时忽略 prompt。期望 reward 是：

\[
J(\theta)=\sum_y \pi_\theta(y)r(y)
\]

意思是：把每个可能回答的 reward，乘以模型生成它的概率，再全部相加。

对参数求导：

\[
\nabla_\theta J
=
\sum_y r(y)\nabla_\theta\pi_\theta(y)
\]

reward 是外部评分，不对模型参数求导；会随参数变化的是回答概率 \(\pi_\theta(y)\)。

接着使用：

\[
\nabla_\theta\log\pi_\theta(y)
=
\frac{\nabla_\theta\pi_\theta(y)}
{\pi_\theta(y)}
\]

移项得到：

\[
\nabla_\theta\pi_\theta(y)
=
\pi_\theta(y)\nabla_\theta\log\pi_\theta(y)
\]

代回去：

\[
\nabla_\theta J
=
\sum_y
\pi_\theta(y)r(y)
\nabla_\theta\log\pi_\theta(y)
\]

而“按照概率 \(\pi_\theta(y)\) 加权求和”正是期望的定义，所以：

\[
\boxed{
\nabla_\theta J
=
\mathbb E_{y\sim\pi_\theta}
\left[
r(y)\nabla_\theta\log\pi_\theta(y)
\right]
}
\]

直观理解是：

> 不必对离散采样过程求导，只需采样一个回答，用它的 reward 加权该回答的 log-prob 梯度。

例如采到一个正确回答，\(r=1\)，就沿着“提高该回答 log-prob”的方向更新；如果 \(r=0\)，它在基础 REINFORCE 中不产生更新。加入 advantage 后，则好于平均的回答提高概率，差于平均的回答降低概率。
