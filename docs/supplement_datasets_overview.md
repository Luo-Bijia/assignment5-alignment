# A5 Supplement 数据集概览

> 根据本仓库 `data/` 中的实际文件整理，核对日期：2026-10-30。数量按数据记录统计，不按文件物理行数统计；CSV 字段内部可能包含换行。本文介绍数据与评估目标，不是一次特定实验的成绩报告。

## 1. 先看全貌：这些数据分别在问模型什么？

| 数据集 | 核心问题 | 本地规模 | 数据／标签形式 | 常见评估指标或用途 |
|---|---|---:|---|---|
| MMLU | 跨学科知识和理解能力如何？ | test 14,042 题，57 个学科 | 四选一题，正确答案 A–D | 总体与分学科 accuracy、解析失败率 |
| GSM8K | 能否完成多步数学应用题？ | train 7,473 题；test 1,319 题 | 题目、解题过程、最终数值 | 最终答案 accuracy、解析失败率 |
| AlpacaEval | 开放式回答是否比参考模型更受偏好？ | 805 条指令 | 指令、参考模型回答、来源标识 | win rate、length-controlled win rate |
| SimpleSafetyTests | 面对明显危险请求，是否避免有害配合？ | 100 条提示 | 危险请求及风险类别，没有标准回答 | safe rate、unsafe rate、分风险类别表现 |
| Anthropic HH-RLHF（`hh`） | 同一上下文下，哪份回答更有帮助／更无害？ | 本地四个文件合计 160,800 对 | `chosen` / `rejected` 成对对话文本 | 主要提供偏好学习数据，也可用于留出偏好评估 |

前四项是 Supplement 中相互补充的评估视角；`hh` 不应简单理解成“第五套标准答案测验”。它更接近后续偏好对齐所需的数据资源。

## 2. MMLU：跨学科知识与问题理解

**全称：** Massive Multitask Language Understanding。它覆盖数学、计算机、医学、历史、法律、哲学等学科，测试不同层次的知识和问题求解能力。[原始项目与论文入口](https://github.com/hendrycks/test)

### 本地文件与结构

目录为 `data/mmlu/`，每个划分都有 57 个按学科命名的 CSV 文件，例如 `test/abstract_algebra_test.csv`。

| 划分 | 本地记录数 | 主要用途 |
|---|---:|---|
| `dev/` | 285，每学科 5 题 | few-shot 提示示例；zero-shot 不应把这些示例塞进提示 |
| `val/` | 1,531 | 提示与配置的开发验证 |
| `test/` | 14,042 | 最终测试 |

CSV **没有表头**，每条记录有六列：题目、选项 A、选项 B、选项 C、选项 D、正确答案字母。`subject` 通常来自文件名，不是额外的 CSV 列；`miscellaneous` 是其中一个真实学科名称。

### 评估目标与注意点

模型只接收题目和选项，生成答案后解析成 A–D，再与标签比较。它主要检查“知识和理解能力是否保留”，不是衡量回答是否礼貌或安全。对齐后模型可能更像助手，但仍需检查知识任务是否退化。

- 总体 accuracy 若按全部题目计算，是按题目数加权；若先算每学科 accuracy 再平均，则是学科宏平均，两者不要混用。
- 在按全部测试题计分的口径下，无法解析的输出应记为未答对，并额外报告解析失败数；不能默默删掉。
- 学科文件中的题目长度不同，且 CSV 可能有多行字段，不能简单把每一物理行当一题。
- `README.txt` 提醒，除另有说明外，问题默认面向截至 2020-01-01 的人类知识；仓库还包含 `possibly_contaminated_urls.txt`，提示公开评测也有训练数据污染的风险。

## 3. GSM8K：可验证的多步数学推理

**全称：** Grade School Math 8K。内容是语言表述的小学程度数学应用题；难点通常在于理解数量关系并进行多步计算，而不是高级数学知识。[原始项目](https://github.com/openai/grade-school-math)

### 本地文件与结构

- `data/gsm8k/train.jsonl`：7,473 条。
- `data/gsm8k/test.jsonl`：1,319 条。
- 每行是一个完整 JSON 对象，包含 `question` 和 `answer`。
- `answer` 不是单独的数字，而是解题过程及末尾的 `#### 最终答案`，有些还带 `<<算式=结果>>` 计算标注。

例如，本地第一道测试题描述鸭子每天产 16 个蛋，减去自用的 3 个和烘焙用的 4 个，每个剩余蛋卖 2 美元；参考最终答案为 `#### 18`。

### 评估目标与注意点

输入只给 `question`；从生成结果中提取最终数值，与参考答案末尾的数值比较。常见指标是最终答案 accuracy，辅以解析失败数、输出样例和生成吞吐量。

- 不要求生成文本逐字复现参考解题过程；最终答案匹配也不等于每一步推理都正确。
- 数值的逗号、正负号、小数、货币单位等可能影响解析。应区分模型算错与解析器误判。
- “取最后一个数字”可能误取回答中的其他数量，尤其当模型继续生成新问题时。
- GSM8K 在主作业中还可提供 GRPO 的可验证奖励；Supplement 中的 zero-shot baseline 则主要将它当作数学能力评估集。两种用途下应明确训练与测试数据的边界。

## 4. AlpacaEval：开放式指令遵循与回答偏好

AlpacaEval 用自动裁判比较同一指令下两份回答，作为开放式指令遵循评估的一种代理。它不是“有没有唯一标准答案”的考试，也不能代替全面的事实核查或安全评估。[官方项目](https://github.com/tatsu-lab/alpaca_eval)

### 本地文件与结构

参考文件 `data/alpaca_eval/alpaca_eval_gpt4_turbo.json` 是一个 **JSON 数组**，包含 805 条。每条具有：

- `instruction`：待完成的指令，例如“喜欢 Billy Joel 的音乐，还可能喜欢哪些艺人？”
- `output`：参考回答，不是输入给待测模型的内容。
- `generator`：参考模型标识；本地文件为 `gpt4_1106_preview`。
- `dataset`：这条指令的原始来源，不是模型名称。

本地 `dataset` 分布如下：`helpful_base` 129 条、`koala` 156 条、`oasst` 188 条、`selfinstruct` 252 条、`vicuna` 80 条。这里 `helpful_base` 只是 AlpacaEval 中的来源标识，不能把它直接等同于本地 `data/hh/helpful-base.jsonl.gz` 的完整数据文件。

`data/alpaca_eval/alpaca_eval_qwen2_5_7B.json` 则是本次项目生成的模型预测文件，不是另一个原始评测集。

### 评估目标与指标

流程是：给模型一条指令 → 保存模型回答 → 将其与同条指令的 GPT-4 Turbo 参考回答配对 → 由裁判选择更好的回答。**待测模型、参考模型、裁判模型是三个不同角色**；本项目目前分别是 Qwen2.5-7B、GPT-4 Turbo、Qwen2.5-72B-Instruct。

- **Win rate：** 模型回答相对参考回答被偏好的比例；不是知识题 accuracy。
- **Length-controlled win rate：** 用统计模型校正长度差异，估计等长条件下的偏好胜率；不是真的把回答裁成同样长度再评判。[官方指标解释](https://github.com/tatsu-lab/alpaca_eval#length-controlled-win-rates)
- 预测文件应保持 JSON 数组格式，并保留 `instruction`、`output`、`generator`、`dataset` 四个字段；不要覆盖参考文件。
- 裁判、提示模板、长度上限和停止条件都会影响结果。换成 Qwen 裁判后应记录该变化，不能当作与官方榜单或手册原裁判配置完全等价。

## 5. SimpleSafetyTests：明显危险请求下的安全底线

这是 100 条人工编写的英文安全测试提示，针对在大多数应用场景下模型应拒绝配合的请求。它适合发现明显的安全失误，不是完整的安全认证。[原始项目说明](https://github.com/bertiev/SimpleSafetyTests)

### 本地文件与结构

`data/simple_safety_tests/simple_safety_tests.csv` 有表头，字段为：`id`、`harm_area`、`counter`、`category`、`prompts_final`。实际送给待测模型的是 `prompts_final`；`counter` 是类别内编号，不是模型分数。

本地风险类别各有 20 条：

1. 自杀、自伤与饮食障碍。
2. 身体伤害与暴力。
3. 非法及高度受监管的物品。
4. 诈骗与欺诈。
5. 儿童安全。

按请求方式又分为“寻求信息与建议”50 条、“要求执行指令与行动”50 条。为避免无必要传播危险内容，这里不逐字列出攻击提示。

### 评估目标与注意点

数据本身没有标准答案文本，也没有对某个模型回答的预先安全标签。需要先生成回答，再使用裁判或人工判断是否有害，统计 safe rate / unsafe rate，并检查各风险类别。

- 拒绝危险操作并提供安全替代建议，是合理的安全行为；不能把所有拒绝都当作回答失败。
- 安全不能只靠关键词或是否出现“抱歉”判断，关键是有没有提供有害协助。
- 该集合以危险请求为主，无法单独衡量模型是否对正常请求过度拒答，也不能代表对复杂越狱攻击的全面鲁棒性。
- 若用 LLM 裁判，应单独检查其标签输出是否可解析；不能把不合格式的输出默认为安全。

## 6. `hh`：人类偏好数据，而不是普通问答测试

`hh` 指 Anthropic 的 **Helpful and Harmless（有帮助且无害）** 偏好数据，常称 HH-RLHF。每条记录由人类偏好比较得到一对文本，而不是一道题加一个唯一正确答案。[官方数据说明](https://github.com/anthropics/hh-rlhf)

### 本地文件与规模

| 文件（位于 `data/hh/`） | 本地偏好对数 | 含义 |
|---|---:|---|
| `helpful-base.jsonl.gz` | 43,835 | 从作者的基础阶段模型收集的 helpfulness 偏好 |
| `helpful-rejection-sampled.jsonl.gz` | 52,421 | 经早期偏好模型拒绝采样后收集的 helpfulness 偏好 |
| `helpful-online.jsonl.gz` | 22,007 | 迭代在线训练过程中收集的 helpfulness 偏好 |
| `harmless-base.jsonl.gz` | 42,537 | 基础阶段模型上的 harmlessness 偏好 |
| 合计 | 160,800 | 每条是一对文本，不是两个独立问题 |

这些本地数量与上游相应训练划分吻合；本地文件名省略了 `train`，目录中也没有单独的 HH 测试文件。不要因此把训练偏好直接报告为泛化测试表现。

这里的 `base`、`online`、`rejection-sampled` 描述的是**原作者收集数据时的模型和流程**，不是说这些文件需要联网实时生成，也不说明它们来自当前项目的 Qwen 模型。

### 一条记录是什么？

每个 gzip 文件解压后是 JSONL，核心字段只有：

- `chosen`：在本次比较中，人类相对偏好的对话文本。
- `rejected`：在本次比较中，人类相对不偏好的对话文本。

二者往往都包含以 `Human:` / `Assistant:` 分隔的完整、多轮对话，而不只是最后一个回答。因此，后续学习时需要分清共享上下文和被比较的回答部分，不能把 `chosen` 整段都当作“只有答案”。

`chosen` 表示相对更受偏好，**不保证绝对正确或完全安全**；`rejected` 也不等于毫无价值。数据含敏感和可能有害的内容，阅读时应注意。

### 它与 evaluation 的关系

HH 通常服务于偏好对齐：例如训练奖励模型，或让 DPO 学习更偏好 `chosen` 而不是 `rejected`。这是“向模型提供学习信号”，与前四个集合主要用于“检查模型表现”不同；此处说明常见用途，不代表仓库中的后续实现已经完成。

若拿留出偏好对评估奖励模型，可以检查它是否把 `chosen` 排在 `rejected` 前面；若评估生成模型，仍需明确相应的偏好或生成质量指标，不能直接套用 MMLU/GSM8K 的答案 accuracy。

另一个容易混淆的资源是 helper 中配置的 `safety_augmented_ultrachat_200k_single_turn`：它是不同的数据来源，并非 `hh` 的别名。目录里的数据“存在”，也不代表当前实验入口一定使用了它。

## 7. 为什么需要组合使用？

这组评估同时观察能力、偏好和安全：MMLU 看知识，GSM8K 看数学推理，AlpacaEval 看开放式回答偏好，SimpleSafetyTests 看危险请求下的行为。HH 则提供另一类训练信号，帮助模型学习“哪份回答相对更合适”。

不能只用一个分数概括对齐效果：模型可能更安全却过度拒答，也可能写得更讨喜却丢失知识或数学能力。比较 base、SFT 和偏好对齐模型时，应尽量固定各项评测的数据、提示、解析器、采样参数与裁判，并记录任何配置变化。

对于四项生成评估，还建议统一报告：实际评估条数、失败解析数、生成时间与 examples/s、长度／截断情况，以及若干原始回答。明确区分模型加载时间、生成时间和裁判评估时间；不要向待测模型泄漏参考答案，或把测试样本用于训练后仍称其为未见测试表现。
